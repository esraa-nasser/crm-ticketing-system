## Story Goal

Create the first real domain type in the product, and the first consumer of the mapping convention story 02 established.

1. `Ticket` exists as an aggregate that enforces its own invariants — invalid tickets cannot be constructed, and illegal status moves are refused by the domain rather than by the UI or a database constraint.
2. The status workflow is declared **once**, in the domain, as a transition table.
3. `Ticket` maps to a `ticket` table through an `IEntityTypeConfiguration<Ticket>`, discovered automatically, with snake_case names applied by the existing convention.
4. A migration named `AddTicket` creates that table — the first migration in the repo whose `Up()` does anything.

The story stops at the database boundary. No endpoint, no contract, no UI.

Explicit numeric values on both. They are persisted as strings, but pinning the numbers stops a later reorder from silently changing meaning if anyone ever switches storage.

### 2 — The transition table

**Create file: `src/CrmTicketing.Domain/Tickets/TicketStatusTransitions.cs`**

```csharp
namespace CrmTicketing.Domain.Tickets;

/// <summary>
/// The single declaration of which status moves are legal. Nothing else in the
/// solution may encode this - not the API, not the client, not the database.
/// </summary>
public static class TicketStatusTransitions
{
    public static bool IsAllowed(TicketStatus from, TicketStatus to);
    public static IReadOnlySet<TicketStatus> AllowedFrom(TicketStatus from);
}
```

The table, exactly:

| From | Allowed to |
|---|---|
| `New` | `Open`, `Closed` |
| `Open` | `Pending`, `Resolved`, `Closed` |
| `Pending` | `Open`, `Resolved`, `Closed` |
| `Resolved` | `Open`, `Closed` |
| `Closed` | *(none)* |

Eleven legal pairs out of twenty-five. Back it with a `FrozenDictionary<TicketStatus, FrozenSet<TicketStatus>>` initialised once in a static constructor. `IsAllowed(x, x)` returns **false** — a transition to the current status is a no-op the caller should not be making, and silently allowing it hides bugs.

`AllowedFrom` exists so a future UI can render only legal actions without duplicating the table. It returns an empty set for `Closed`.

### 3 — The title value object

**Create file: `src/CrmTicketing.Domain/Tickets/TicketTitle.cs`**

```csharp
public sealed record TicketTitle
{
    public const int MaxLength = 200;
    public static TicketTitle Create(string? value);   // trims, then validates
    public string Value { get; }
    public override string ToString() => Value;
}
```

`Create` throws `ArgumentException` naming the parameter for null, empty, whitespace-only, or over `MaxLength` **after trimming**. A private constructor keeps `Create` the only way in.

Description gets no value object — it has one rule (length) and no behaviour. Constitution §VII: three strikes before abstraction.

### 4 — The domain exception

**Create file: `src/CrmTicketing.Domain/Tickets/InvalidTicketTransitionException.cs`**

```csharp
public sealed class InvalidTicketTransitionException : InvalidOperationException
{
    public InvalidTicketTransitionException(TicketStatus from, TicketStatus to);
    public TicketStatus From { get; }
    public TicketStatus To { get; }
}
```

Message shape: `"A ticket cannot move from Closed to Open."` The `From`/`To` properties let the API map this to a 409 later without parsing the message. Include the three standard constructors that CA1032 requires, or suppress it with a comment — do not leave a bare warning.

### 5 — The aggregate

**Create file: `src/CrmTicketing.Domain/Tickets/Ticket.cs`**

```csharp
public sealed class Ticket : Entity
{
    public static Ticket Open(
        Guid id,
        TicketTitle title,
        string description,
        Guid requesterId,
        DateTimeOffset createdAt,
        TicketPriority priority = TicketPriority.Normal,
        string? category = null);

    public TicketTitle Title { get; private set; }
    public string Description { get; private set; }
    public TicketStatus Status { get; private set; }
    public TicketPriority Priority { get; private set; }
    public string? Category { get; private set; }
    public Guid RequesterId { get; }
    public Guid? AssigneeId { get; private set; }
    public DateTimeOffset CreatedAt { get; }
    public DateTimeOffset UpdatedAt { get; private set; }

    public void TransitionTo(TicketStatus target, DateTimeOffset at);
    public void Assign(Guid assigneeId, DateTimeOffset at);
    public void Unassign(DateTimeOffset at);
    public void ChangePriority(TicketPriority priority, DateTimeOffset at);
}
```

Rules:

- The factory is named `Open` rather than `Create` because it names the business event. Status is set to `New` internally; the caller cannot choose it.
- `description` is trimmed then validated: non-empty, at most **10000** characters, else `ArgumentException` naming the parameter.
- `category` is trimmed when present; an empty or whitespace string becomes `null`; over 100 characters throws.
- `requesterId` must not be `Guid.Empty`.
- `TransitionTo` consults `TicketStatusTransitions.IsAllowed` and throws `InvalidTicketTransitionException` when false. On success it sets `Status` and `UpdatedAt`.
- `Assign` rejects `Guid.Empty`, and rejects any ticket whose `Status` is `Closed` — throw `InvalidOperationException` with a message naming the status. `Unassign` sets `AssigneeId` to null and is legal in any non-`Closed` status.
- Every mutator takes `DateTimeOffset at` and assigns it to `UpdatedAt`. **No call to `DateTime.UtcNow` or `TimeProvider` anywhere in the domain** — the caller owns the clock.
- A **private parameterless constructor** is required for EF Core materialisation. Mark it `private Ticket() { }` with a comment saying it exists for EF only, and initialise non-nullable reference properties with `null!` there. This is the one place the "no invariant-bypassing constructor" rule bends, and it bends because EF needs it — say so in the comment.

### 6 — The persistence mapping

**Create file: `src/CrmTicketing.Infrastructure/Persistence/Configurations/TicketConfiguration.cs`**

```csharp
internal sealed class TicketConfiguration : IEntityTypeConfiguration<Ticket>
{
    public void Configure(EntityTypeBuilder<Ticket> builder);
}
```

- `builder.ToTable("Ticket")` — pass PascalCase; `ApplySnakeCaseNames` rewrites it to `ticket`. Do **not** pre-lowercase names here, or the convention becomes untestable.
- `HasKey(t => t.Id)`.
- `Title` is a value object: map it with `builder.Property(t => t.Title).HasConversion(v => v.Value, v => TicketTitle.Create(v)).HasMaxLength(TicketTitle.MaxLength).IsRequired()`.
- `Description` — `IsRequired()`, `HasMaxLength(10000)`.
- `Category` — optional, `HasMaxLength(100)`.
- `Status` and `Priority` — `.HasConversion<string>().HasMaxLength(20).IsRequired()`.
- `CreatedAt` / `UpdatedAt` — `timestamp with time zone` is Npgsql's default for `DateTimeOffset`; do not override it.
- Index `RequesterId`, and index `Status` — the two columns every later query filters on.

`internal sealed` is deliberate: nothing outside Infrastructure should reference a configuration class, and `ApplyConfigurationsFromAssembly` finds internal types.

**No change** to `CrmDbContext.cs`. Discovery is automatic; if it needs editing, something is wrong.

## Edge Cases & Failure Modes

- **Transition to the same status.** `IsAllowed(Open, Open)` is false, so `TransitionTo(Open)` on an open ticket throws. Deliberate: a no-op transition is almost always a caller bug.
- **Whitespace-only title.** `"   "` must be rejected, not stored as an empty string. `TicketTitle.Create` trims *before* the empty check.
- **Title of exactly 200 characters** is valid; 201 is not. Test both sides of the boundary, not just the failing one.
- **Trailing whitespace pushing a title over the limit.** `"x" * 199 + "  "` trims to 199 and is valid. Trim first, then measure.
- **Category as empty string.** Normalised to `null`, so the database never holds `''` and `null` in the same column meaning the same thing.
- **`Guid.Empty` requester** must throw from the factory, not from the `Entity` base — the base only guards the entity's own id.
- **Assigning a closed ticket** throws `InvalidOperationException`, not `InvalidTicketTransitionException` — no status change is being attempted.
- **EF's private constructor.** It bypasses every invariant by design. That is safe only because EF is the sole caller; if anything else uses reflection to construct a `Ticket`, this guarantee is gone. Comment it.
- **Value-object conversion on `Title`.** EF calls `TicketTitle.Create` when materialising. A row that somehow holds an invalid title will throw on read rather than load silently — accepted, and worth knowing when someone edits the database by hand.
- **Uncertainty to surface — `Closed` is terminal.** The intake fixes this. If a reviewer wants `Closed -> Open`, it is one row in the transition table plus a test change, but it must be decided **before** implementation, not during. Stop and revise the plan if it comes up.

## Migration / Rollback

`AddTicket` is additive: one `CREATE TABLE`, no data movement, no destructive change. `Down()` drops the table.

Rollback before deployment is `dotnet ef migrations remove`. After deployment it is `dotnet ef database update InitialCreate`, which runs `Down()` and drops `ticket` **with any rows in it** — acceptable now because no environment holds real data, and worth stating plainly so it is not assumed later.

Half-applied risk: if the migration is generated but the configuration is subsequently changed without regenerating, the snapshot and the model disagree and the *next* migration will contain confusing diffs. If you change `TicketConfiguration` after generating, remove and regenerate rather than editing the migration.
